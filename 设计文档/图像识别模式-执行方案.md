## 一、已确认的关键决策

### 1.1 模式范围

| 阶段 | 模式 | 说明 |
|---|---|---|
| 开局（人格/EGO/编队/星光/饰品） | **全手动** | 不接入图像识别 |
| 地牢（卡包→战斗/事件/商店→关底） | **自动** | 选完开局饰品后等待卡包页面出现，自动激活 |

### 1.2 技术决策

| 决策点 | 结论 |
|---|---|
| 游戏分辨率 | 全屏 2560×1440 渲染，16:9 完美填充 / 16:10 上下黑边 |
| 技术栈 | Python 子进程 (OpenCV + mss + PaddleOCR)，stdin/stdout JSON 行协议 |
| 检测频率 | 每 500ms 截屏一次 |
| 指示图标 | 全屏透明覆盖窗口，`setIgnoreMouseEvents(true)`，Canvas 绘制，穿透点击 |
| 参考图采集 | 开发者面板集中采集，用户按指引在游戏中截取各环节特征区域。坐标归一化到 2560×1440 游戏区域，兼容 16:9/16:10 |
| 确认方式 | 传呼机完成/失败按钮保持手动点击 |
| 指令完成检测 | **不做**（技能图标种类太多，识别不可靠） |

### 1.3 地牢内环节清单

| # | 环节 | 识别方式 | 指示图标 | 说明 |
|---|---|---|---|---|
| 1 | **卡包选择** cardpack | OCR "选择X层主题卡包" + 放大镜图标定位 + 模板匹配卡包图 | ✅ 高亮框标注选中卡包，箭头指向刷新 | 每层第一个。横向一排 3~5 个。选择=按住下拉（不模拟） |
| 2 | 路线选择 route | **不识别** | — | 玩家自己选 |
| 3 | **战斗** combat | 底部三段式结构（技能上排+下排+头像行）。技能槽按形状/颜色从左到右编号 | ✅ 标注"上排第X个/下排第X个"；守备标注槽位；金枝右上角 | 每回合一条指令。头像行消失→再出现=新回合。**不匹配人格头像**，靠槽位编号定位 |
| 4 | **事件** event | UI 特征定位 | ✅ 选项按钮 | — |
| 5 | **判定** judgment | UI 特征定位 | ✅ 罪人头像 | 事件中触发 |
| 6 | **奖励卡** event_reward | UI 特征定位 | ✅ 奖励卡牌 | 战斗/事件后 |
| 7 | **商店** shop | UI 特征定位 | ✅ 操作按钮/商品 | 每层倒数第二个节点（普通/特殊） |
| 8 | **隐藏BOSS** hidden_boss | 检测警告动画 | ✅ 进入/跳过按钮 | 特殊触发 |
| 9 | **关底奖励** boss_reward | UI 特征定位 | ✅ 奖励选项 | 每层最后一个，完成后楼层+1 → 回到卡包 |

BOSS 战斗复用 combat 环节。

### 1.4 编队窗口改造

- 从 3×4 改为 **上6下6** 布局（12 个固定槽位，2 排×6 列）
- 每个槽位：罪人证件照 + 名字。已分配 = 变暗 + 居中金色序号，未分配 = 正常亮色无序号
- 点击逻辑不变：按点击顺序分配 1→12，再点取消并前移
- 证件照从 huijiwiki 爬取存到 `resources/sinners/`

### 1.5 附加需求

- 自定义快捷键：完成/失败可绑定快捷键
- 完成/失败按钮加按下动画

## 三、架构总览

```
Limbus Company (游戏 2560×1440)
    │ mss 截屏
    ▼
Python 视觉引擎 (tools/vision_engine.py)
    - 黑边检测 → 游戏区域定位
    - 环节检测 (参考图特征匹配)
    - 卡包识别 (图标模板匹配 + OCR)
    - UI 元素定位 (按钮/选项坐标)
    stdin/stdout JSON 行协议
    │
    ▼
Node.js 视觉管理器 (src/visionManager.js)
    - spawn/kill Python 子进程
    - 请求-响应配对
    - 超时 5s / 崩溃自动重启(最多3次)
    │
    ▼
main.js — 自动模式状态机
    - 地牢入口检测（等待卡包画面）
    - 每 500ms 检测循环
    - 环节变化 → 自动生成指令
    - 指示图标窗口管理
    │
    ├──→ 传呼机 (行为不变，F9 自动模式禁用)
    └──→ 指示图标窗口 (全屏透明 Canvas)
```
